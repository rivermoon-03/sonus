# 프로토콜 기록

이 디렉터리는 사용자가 소유한 WH-1000XM6에 데이터를 보내고 응답을
확인해 얻은 RFCOMM 제어 프로토콜 관찰 결과를 기록한다. 목적은 기기와의
호환성 확보이다. Sony의 소스 코드, 펌웨어 이미지, 분해한 바이너리는
포함하지 않으며 앞으로도 추가하지 않는다. 여기에는 관찰한 통신 데이터
형식(데이터 묶음의 바이트 구성, 명령 ID, 데이터 모양)만 기술한다. 이는
상호 운용을 위한 리버스 엔지니어링에 해당한다(EU Software Directive
Art. 6, DMCA §1201(f), 대한민국 저작권법 제101조의4 참조).

## 데이터 묶음 구조(XM6 실측, 구현 완료 및 검증)

`src/sonus/protocol/framing.py`는 WH-1000XM6에서 관찰한 데이터 묶음 형식을
구현한다. 처음 구현한 XM4/XM5 기반 가설은 2026-08-15에 WH-1000XM6으로
시험한 결과 실제 형식과 달랐다. 아래에서 확인한 구성은 독립적으로 개발된
[SonyHeadphonesClient MDR 패킷 구현](https://github.com/mos9527/SonyHeadphonesClient/blob/v1-compat/libmdr/src/Command.cpp)과
일치한다.

| 항목 | 크기 | 설명 |
|---|---|---|
| START | 1바이트 | `0x3E` |
| data_type | 1바이트 | `0x01` ACK, `0x0C` DATA_MDR, `0x0E` DATA_MDR_NO2 |
| seq | 1바이트 | 번갈아 쓰는 순서 번호(관찰값 `0` 또는 `1`) |
| length | 4바이트 | payload 길이, 부호 없는 빅 엔디언 |
| payload | N바이트 | 명령별 데이터 |
| checksum | 1바이트 | data_type+seq+length+payload의 바이트 합을 256으로 나눈 나머지 |
| END | 1바이트 | `0x3C` |

특수 바이트 처리: START와 END 사이에 `0x3E`/`0x3C`/`0x3D`가 나오면
`0x3D`와 `(해당 바이트 - 0x10)`으로 바꿔 보낸다.

RFCOMM은 연속된 바이트를 전달한다. 한 번의 `recv()`에 여러 데이터
묶음이 함께 들어올 수도 있고, 하나가 여러 번에 나뉘어 들어올 수도 있다.
따라서 해석기는 `recv()` 결과 하나를 완성된 데이터 하나로 가정하지 않고,
조각난 데이터를 내부에 모아 이어 붙여야 한다.

## 기기 검증 기록

### 2026-08-15 — 교정 구현 회귀 검증

- `sonus probe --mac 58:18:62:1F:C9:CB`가 RFCOMM channel 9를 탐색했다.
- 요청 `3e0c000000000200000e3c`에 ACK와 protocol-info 응답을 수신했다.
- 응답 payload는 `0100030030320000`이며 checksum 검증을 통과했다.
- ACK와 응답의 병합 수신, 큰 알림의 분할 수신을 단위 테스트로 고정했다.

### 2026-08-15 — WH-1000XM6 프로토콜 정보 테스트

- 기기: 저장소에 테스트 MAC 주소로 설정한 사용자 소유 WH-1000XM6.
- SDP 제조사 서비스에서 RFCOMM 채널 9를 확인했다. 실제 응답은 16비트
  DES 길이(`0x36`)와 바깥쪽 서비스 레코드 묶음을 사용했다. 이 동작은
  `test_parse_rfcomm_channel_accepts_real_xm6_two_byte_des_lengths`로 검사한다.
- 연결만 한 상태에서는 12초 동안 수신된 데이터가 없었다.
- 기존 가설인 `sonus send --type 0x01 --payload ""`은 모든 재시도에서
  응답 시간을 초과했다.
- 올바른 프로토콜 정보 요청:
  `3e0c000000000200000e3c` (`DATA_MDR`, seq 0, payload `0000`).
- 기기 ACK: `3e010100000000023c`.
- 기기 응답: `3e0c010000000801000300303200007b3c`. 해석 결과 data type
  `0x0C`, seq 1, payload `0100030030320000`이며 checksum이 올바르다.
- 응답에 ACK를 보낸 뒤 기기가 유효한 `0x0C` 데이터를 추가로 보내,
  통신 중 비동기 알림이 도착할 수 있음을 확인했다.
- 민감 정보를 제거한 원본 데이터는 다음 경로에 저장한다.
  `tests/fixtures/captures/2026-08-15-xm6-protocol-info.jsonl`.

### 2026-08-16 — 상태와 설정 탐색

XM6 펌웨어 `3.1.5`에서 Table 1은 45개, Table 2는 16개 지원 기능을 광고했다.
지원 목록과 아래 원시 응답은 MAC 주소를 제거해
`tests/fixtures/captures/2026-08-16-xm6-state.json`에 저장했다.

| 기능 | 확인한 값 | 읽기 | 쓰기 |
|---|---|---:|---:|
| 모델/펌웨어 | WH-1000XM6 / 3.1.5 | 확인 | 해당 없음 |
| 배터리/충전 | 83%, 충전 아님 | 확인 | 해당 없음 |
| 오디오 코덱 | LDAC | 확인 | 해당 없음 |
| 연결 우선 모드 | 음질 우선 | 확인 | 미검증 |
| ANC/주변음 | 전체 상태, 주변음 단계 16 | 확인 | 미검증 |
| 이퀄라이저 | 사용자 설정 1, 10밴드 | 확인 | 미검증 |
| DSEE Extreme | 자동 | 확인 | 확인·자동 복원 시험 통과 |
| 착용 감지 자동 일시정지 | 켜짐 | 확인 | 미검증 |
| 착용 감지 자동 전원 끄기 | 사용 안 함 | 확인 | 미검증 |
| Speak-to-Chat | 꺼짐 | 확인 | 미검증 |
| 음성 안내 | 켜짐, 일본어, 음량 보정 0 | 확인 | 미검증 |
| 착용 상태 | 착용하지 않음 | 확인 | 해당 없음 |
| 안전 청취/안전 음량 | 켜짐/켜짐 | 확인 | 미검증 |
| LE Audio 연결 상태 | 현재 Classic 연결에서 응답 없음 | 미확인 | 미검증 |

DSEE는 원값 조회, 반대값 설정, 설정 응답 확인, 원값 복원, 복원 재조회 순서의
하드웨어 테스트를 통과했다.

### 2026-08-17 — 설정 쓰기와 원상 복원 검증

같은 XM6와 펌웨어 `3.1.5`에서 각 항목을 원값 조회 → 대체값 쓰기 → 재조회 비교 →
원값 쓰기 → 재조회 비교 순서로 독립 실행했다. DSEE, 10밴드 EQ, 착용 감지 자동
일시정지, Speak-to-Chat, Bluetooth 연결 모드, 착용 해제 시 자동 전원 끄기,
음성 안내, 음성 안내 음량의 8개 항목이 모두 통과했다. EQ와 연결 모드의 SET은
ACK만 반환하므로 별도 GET으로 확인한다. 음성 안내 SET 알림에는 언어가 빠지므로
이 역시 전체 GET 값으로 확인한다. 식별자를 제거한 결과는
`tests/fixtures/captures/2026-08-17-xm6-verified-writes.json`에 저장했다.

ANC/주변음은 미착용 상태에서 GET의 enabled 값이 저장 설정이 아니라 현재 운용
상태로 정규화되었다. 원래 선택을 정확히 증명할 수 없으므로 쓰기를 열지 않았다.
안전 청취와 안전 음량 응답도 현재 설정값이 아닌 지원 여부로 판정되어 조회 전용을
유지한다. 전원 끄기·초기화·페어링·펌웨어 관련 명령은 실험하지 않았다.

## XM6가 광고한 기능 범위

Table 1 지원 목록에서 배터리, 코덱, DSEE, EQ, 적응형 ANC/주변음, 재생 제어,
착용 감지, Speak-to-Chat, 자동 전원 끄기, 연결 모드, BGM 효과, Cinema Upmix,
Quick Access, 자동 재생, 헤드 트래킹, 일반 설정 묶음을 확인했다. Table 2에서는
음성 안내와 음량, 안전 청취, 안전 음량, LE Audio 상태/전환, Quick Access 간편
설정, Sony 음성 비서, 통화 마이크 조작, 헤드셋 자동 전환, 충전 중 사용과 USB
침수 감지 지원을 확인했다.

지원 목록은 "명령 실행 가능"을 뜻하지 않는다. 다음 항목은 공식 XM6 기능에는
있지만 기기 단독 명령 형식 또는 안전한 복원 방법을 아직 확인하지 못했다.

- 터치 패널, NC/주변음 버튼 전환 패턴, 멀티포인트
- 자동 주변음과 감도, Adaptive Sound Control
- EQ 프리셋 변경과 사용자 밴드 저장, Clear Bass
- Quick Access, Auto Play, 서비스 연결
- 공간 음향, 헤드 트래킹, 360 Upmix for Cinema
- 통화 사이드톤, 헤드 제스처, Voice Control 언어

전원 끄기, 초기화, 페어링 기기 관리, 펌웨어 갱신, identity resolving key 조회는
지원 목록에 나타나더라도 안전 정책상 실행 후보에서 제외한다.

펌웨어나 바이너리를 포함·배포하거나 보호 장치를 우회하지 않는다. 공개된 독립
구현은 기능 후보를 좁히는 참고 자료로만 사용하고 XM6에서 별도로 확인한다.

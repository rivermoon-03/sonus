# Sonus 전체 설정 쓰기 검증과 데스크톱 GUI 개선 설계

## 목표

WH-1000XM6에서 현재 읽을 수 있는 설정의 쓰기 프로토콜을 사용자 소유 실기기로
검증하고, 검증에 성공한 항목을 Sonus GUI에서 안전하게 조작할 수 있게 한다. GUI는
웹 대시보드 인상을 줄인 컴팩트 데스크톱 설정 앱으로 다듬고, 최초 한 번만 표시되는
Disclaimer 동의 뒤에 쓰기 기능을 제공한다. 완료한 작업은 기존 GUI 작업 브랜치의
이력을 한국어 커밋 두 개로 정리한 뒤 로컬 `main`에 통합하며 원격에는 push하지 않는다.

## 검토한 접근

1. **컴팩트 설정 앱**: 고정 사이드바와 툴바 아래에 상태 요약과 실제 조작 행을
   밀도 있게 배치한다. 현재 기능 수에 맞고 기존 구조를 무리 없이 개선할 수 있어
   선택한다.
2. **마스터-디테일**: 설정 목록과 상세 편집기를 나눈다. 기능 확장에는 유리하지만
   현재 항목 수에는 탐색 단계가 늘고 화면을 과하게 분할한다.
3. **상태 대시보드**: 제품 이미지와 상태 카드를 유지한다. 시각성은 높지만 사용자가
   지적한 웹 대시보드 인상을 충분히 줄이지 못한다.

## 쓰기 검증 범위와 안전 경계

쓰기 후보는 `noise_control`, `equalizer`, `dsee`, `auto_pause`,
`speak_to_chat`, `connection_mode`, `auto_power_off`, `voice_guidance`,
`voice_guidance_volume`, `safe_listening`, `safe_volume`이다. 모델, 펌웨어,
배터리, 코덱과 착용 상태처럼 상태를 나타내는 값은 쓰기 대상이 아니다.

각 후보는 공개된 독립 구현의 명령 구조를 가설로만 참고하고 XM6 펌웨어 3.1.5에서
다음 순서를 모두 통과해야 `Safety.REVERSIBLE`로 승격한다.

1. 원래 값을 읽어 구조와 범위를 검증한다.
2. 부작용이 가장 작은 다른 유효 값을 한 번 쓴다.
3. 쓰기 응답과 별도 재조회 값이 시험값과 일치하는지 확인한다.
4. 같은 세션에서 원래 값을 다시 쓴다.
5. 별도 재조회 값이 원값과 일치하는지 확인한다.

응답 형식, 값 의미 또는 복원 여부가 확실하지 않으면 즉시 중단하고 해당 기능은
읽기 전용으로 유지한다. 연결 모드처럼 연결 자체에 영향을 줄 수 있는 기능은 복원
재연결까지 확인한다. 자동 전원 끄기는 즉시 전원이 꺼지지 않는 긴 시간 값만 시험하고,
음성 안내 언어처럼 자산 다운로드나 추가 외부 동작 가능성이 있는 변경은 활성 상태와
현재 언어를 보존하는 최소 변경만 시도한다.

전원 끄기, 초기화, 페어링 관리, 펌웨어 명령, identity resolving key 조회,
인증·보호 우회는 구현과 실험에서 계속 제외한다. 확인되지 않은 항목을 GUI에서
쓰기 가능한 것처럼 표시하지 않는다.

실측 요청·응답과 판정은 MAC 주소를 제거해 `tests/fixtures/captures/`와
`docs/protocol/README.md`에 날짜, 펌웨어, 시험값, 원복 결과와 함께 기록한다.

## 프로토콜과 디바이스 계층

명령별 디코더와 인코더는 `messages/codec.py`, 선언 정보는
`messages/registry.py`에 둔다. GUI는 원시 payload를 만들지 않고
`SonyXm6Device.get()`과 `set()`만 사용한다. 쓰기 승격된 기능은 인코더, 쓰기 응답
판별자, 쓰기 응답 디코더를 모두 가져야 한다.

`SonyXm6Device.set()`은 설정 응답을 확인한 뒤 결과를 돌려준다. 하드웨어 검증에는
기존 `temporary_setting()`을 확장해 설정 응답뿐 아니라 변경 후 재조회와 복원 후
재조회를 강제한다. 복원 도중 오류가 나면 한 번 더 복원을 시도하고, 성공 여부를
숨기지 않은 전용 오류로 보고한다.

## GUI 쓰기 흐름

Qt 작업자는 연결과 읽기뿐 아니라 한 번에 하나의 설정 쓰기를 직렬 처리한다.
JavaScript는 기능 키와 정규화된 JSON 값만 WebChannel에 전달한다. Python bridge는
Disclaimer 동의, 기능 존재 여부, `writable`, 입력 값 검증을 다시 확인한 뒤 작업자에
요청한다. 프런트엔드 검사만으로 쓰기 권한을 부여하지 않는다.

쓰기 흐름은 다음과 같다.

1. 사용자가 토글, 세그먼트, 선택 메뉴, 슬라이더 또는 EQ 밴드를 변경한다.
2. 해당 컨트롤을 처리 중 상태로 잠그고 Python에 요청한다.
3. Python이 설정 응답을 확인하고 같은 기능을 다시 조회한다.
4. 확인된 값으로 전체 상태를 갱신하고 성공 메시지를 표시한다.
5. 실패하면 마지막 확인값으로 UI를 되돌리고 사람이 읽는 오류를 표시한다.

연결되지 않음, 읽기 전용 기능, 동의하지 않음, 잘못된 값, 응답 시간 초과, 연결 끊김,
복원 실패를 구분한다. raw exception과 원시 payload는 사용자 화면에 노출하지 않는다.

## 최초 Disclaimer

`GuiSettings`의 `legal/disclaimer_accepted` 불리언 값이 참이 아니면 연결 화면보다
먼저 모달을 표시한다. 동의 버튼은 값을 `QSettings`에 즉시 저장하고 앱을 계속
사용하게 한다. 거부 또는 창 닫기는 앱을 종료하므로 동의하지 않은 상태에서 쓰기
경로가 열리지 않는다. 동의 뒤에는 다시 묻지 않는다.

문구는 Sonus가 Sony 비공식 도구라는 점, 사용자 소유·관리 기기에서만 사용해야
한다는 점, 펌웨어에 따라 결과가 달라질 수 있다는 점, 설정 변경 책임, 지원하지 않는
위험 명령 범위를 명시한다.

## 데스크톱 레이아웃과 아이콘

선택한 방향은 컴팩트 설정 앱이다. 앱 전체를 고정 높이 셸로 만들고 사이드바와
상단 툴바는 고정한다. 문서 전체가 아니라 중앙 콘텐츠 영역 하나만 스크롤하며
`scrollbar-gutter: stable`과 일관된 스크롤바 스타일을 적용한다. 모든 보기에는 같은
콘텐츠 최소 높이를 적용해 메뉴 전환 시 폭과 정렬이 움직이지 않게 한다.

사이드바의 `01`부터 `05` 번호는 제거하고 상태, 사운드, EQ, 기기 설정, 정보에
Lucide 계열 SVG 아이콘을 쓴다. 잠금, 새로고침, 테마를 포함한 문자·이모지 아이콘도
모두 같은 로컬 SVG 스프라이트로 교체한다. 네트워크나 CDN에는 의존하지 않는다.
EQ의 10개 밴드 번호는 데이터 식별자이므로 유지한다.

큰 마케팅형 제목, 영문 kicker, 과도한 상하 여백과 반투명 웹 헤더는 줄인다.
상태 화면은 작은 기기 요약, 핵심 지표와 연결 정보로 구성한다. 사운드와 기기 화면은
설명 카드보다 실제 컨트롤 행을 우선한다. 최소 창 크기 800×620에서도 두 열을 억지로
유지하지 않고 한 열 또는 조밀한 행으로 재배치한다.

## 테스트

- 코덱 단위 테스트: 유효 값, 경계 값, 잘못된 값과 정확한 payload를 검증한다.
- 디바이스 단위 테스트: 쓰기 응답 판별, 재조회, 실패, 복원 재시도를 가짜 세션으로
  검증한다.
- GUI 단위 테스트: Disclaimer 저장, 동의 전 쓰기 차단, bridge 값 검증, 작업자 직렬화,
  성공·실패 상태를 검증한다.
- 웹 테스트: Lucide 자산, 이모지 제거, 메뉴 번호 제거, 컨트롤 상태, 안정된 스크롤
  계약과 레이아웃 전환을 검증한다.
- 하드웨어 테스트: 항목별 변경·재조회·원복·원복 재조회를 명시적으로 표식하고 하나씩
  실행한다. 모든 하드웨어 쓰기 테스트는 원값 복원을 `finally`에서 다시 시도한다.
- 전체 검증: 기본 `uv run pytest`, GUI 오프스크린 테스트, Node 테스트, 실행 도움말과
  패키지 빌드를 확인한다.

## 브랜치와 커밋 정리

기존 GUI 작업 브랜치의 시작점과 현재 끝점을 로컬 백업 ref로 보존한다. 완성된 변경을
`main` 기준 한국어 커밋 두 개로 재구성한다.

1. `기능: XM6 설정 쓰기 검증과 디바이스 API 확장`
2. `기능: 데스크톱 GUI 완성과 사용자 경험 개선`

첫 커밋에는 프로토콜, 메시지, 디바이스, 캡처, 관련 테스트와 문서를 넣고 두 번째에는
PyQt6 셸, GUI 자산, Disclaimer, 앱 테스트와 실행 문서를 넣는다. 두 커밋을 검증한 뒤
로컬 `main`을 fast-forward하고 작업 트리를 제거한다. 원격 push는 실행하지 않는다.
